# DATA_DISCREPANCIES.md

Every material difference found between (a) a previously circulated draft's
(V9.2) reported values or claimed artifacts and (b) what the analyst's real
raw-data package and this repository's actual source code support. See
`CLAIM_DATA_MAP.csv` for the complete claim-by-claim table (50 claims);
this file narrates the discrepancies that need more than one row to explain.

## 1. Pre-existing `data/raw/` and `data/benchmarks/` are not verified real data

The repository already contained a `data/raw/` directory and
`data/benchmarks/paper_benchmark_summary.json` before this analysis began,
both self-described as "measured" field data. Comparison against the
analyst's real package (`DATA_PROVENANCE_REPORT.md`) found:

- Identical row counts to several real-package files (209,001 vs 209,001
  lines including header for authorization decisions; 146,401 vs 146,401 for
  sensor transactions) but structurally different content: sequential
  placeholder transaction ids (`SW-00000001...`), a binary-literal
  `decision` vocabulary (`GRANT` vs. the real package's `allowed`/`denied`),
  and suspiciously round latency values (e.g., exactly `1220.0` ms).
- `data/raw/VALIDATION.md` validates its own numbers against a manuscript's
  reported values as "Expected", the reverse of independent validation.
- `data/benchmarks/paper_benchmark_summary.json` is headed with a different
  paper title ("A Decentralized HRBAC Framework for Agricultural Edge-IoT
  Clusters...") and its values (HRBAC TPS 63, RBAC overhead 8.7%, P95 @ 4
  peers 1,480 ms) do not match V9.2's or V10's figures.

**Action:** V10 does not use these files for any claim. They are left
untouched per the requirement not to reorganize unrelated repository
content. This is flagged, not silently ignored.

## 2. The analysis pipeline and independent policy oracle V9.2 describes do not exist in this repository

V9.2 states every number is generated by `analysis/derive_results.py` and
cross-checked against `chaincode/policy-requirements.json`. Neither file
exists anywhere in the repository (confirmed by repository-wide search).
**Action:** V10 builds a new pipeline from scratch (`paper_iot/V10/analysis/scripts/`)
and discloses a newly constructed operation-to-permission oracle
(`06_security_oracle.py`), explicitly labelled as a V10 construction rather
than the missing released file.

## 3. No corrected implementation exists in this repository

V9.2 describes a `chaincode/hrbac-corrected/` package, corrected firmware,
a corrected gateway verifier, regression tests, and a published signature
test vector, tagged `v09-corrected`. None of these exist in the repository
(confirmed by `find`/`grep` across the entire tree and by `git tag -l`
returning no tags). **Action:** V10 reports the corresponding fixes
(role-hierarchy correction, `{253,254,255}` CRT moduli, legacy-compatible
verification) as specified and arithmetically/logically checked, never as
implemented, tested, or measured. Every corrected-version performance,
correctness or security claim from V9.2 is either removed or explicitly
reworded as "not established because no such build exists" (Sec. 4.5,
"The corrected implementation is specified, not released", and Limitation
L6).

## 5. Claims that reproduce exactly

The following V9.2 headline counts reproduce **exactly** from the real data,
with no adjustment: 61-day deployment; 50 sensors, 4 gateways, 4 zones;
209,000 authorization decisions; 146,400 sensor readings; 4,860 (2.33%)
ordinary denials; 99.36% decision-path uptime / 99.84% gateway-hour uptime;
3 outages totalling 9.3 h; 32 peer-scaling runs (8 per configuration), 130
transactions/run; the two-complementary-Latin-square counterbalancing
design; 100 throughput runs (10 x 2 x 5); campaign-sequence-vs-concurrency
correlation r=0.995; 8,000 authorization-boundary attempts, 6 denial
mechanisms, 2,666 role/operation-scored attempts; 131,795 two-residue
reconstructions (90.0%); 100.0000% of readings exceeding the smallest CRT
recovery bound; corrected legal-domain maximum 51,455 and pairwise bound
64,262; 200 revocation-stage records, 132 subjects, 0 with all four stages,
87 appearing once; 973 field revocation denials; CheckAccess mean 280 ms
(SD 40); sensor-write mean 1,220 ms (SD 60), P95 1,319 ms, P99 1,359 ms;
gap 940 ms; span share 26.6% at 4 peers and 39.0% at 32 peers.

This exact reproduction of the great majority of V9.2's headline counts is
itself evidence that the analyst's real-data package is consistent with
(very likely the actual source underlying) the historical measurements
V9.2 described, even though the specific analysis artifacts V9.2 claims to
release from that data are not present in this repository.
