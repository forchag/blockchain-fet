Blockchain access control for Internet of Things systems is commonly evaluated with short laboratory measurements of aggregate throughput and latency, leaving the location of delay within the transaction path and its long-term validity uncertain. We report a \DeploymentDays{}-day Hyperledger Fabric 2.5 deployment on a farm site with \Sensors{} sensors, \Gateways{} gateways and \Zones{} zones, recording \AuthDecisions{} authorization decisions, followed by separately executed controlled experiments and a code-to-specification postmortem, all recomputed here from the analyst-supplied raw traces. An implementation-defined chaincode timer recorded an authorization-associated span averaging \SpanLatencyPeerFour{} ms within the \TotalLatencyPeerFour{} ms write path of the deployed (historical) implementation. Across \PeerRunsPerConfig{} counterbalanced live runs per configuration, verified against the released run manifest, increasing configured logical peer multiplicity from 4 to 32 on four fixed hosts was associated with a \RemainingLatencyDiffFourVThirtyTwo{} ms reduction in the uninstrumented remainder, while the recorded span differed by only \SpanDiffFourVThirtyTwo{} ms between the extreme configurations, inside a $\pm$10 ms exploratory equivalence margin. A separately executed, interleaved single-session experiment found the access-control-enabled path averaged \ThroughputPctDiffMean{}\% lower throughput than the comparison path, with no detected condition-by-concurrency interaction. A structured audit of the deployed chaincode, gateway and firmware identified three cross-layer defect classes -- authorization-policy deviations, invalid two-residue recovery affecting \CrtTwoResidueCount{} readings, and a signature-verification failure combining a signed-message mismatch with fail-open handling of missing signatures -- confirmed directly against the released source, plus a revocation-observability gap preventing episode-level exposure measurement. The corrected policy, encoding and verification behavior is specified and arithmetically checked, but no corrected chaincode, firmware or gateway package exists in the inventoried repository, so corrected-implementation performance and correctness are not established. We release the raw measurements and the reanalysis pipeline that recomputes every number in this article.
